What this route can do

The existing flow retrieves your own data and updates a private JSON file. OneDrive’s existing client syncs it. In an approved Edge/Chrome browser, choose the two files once. Little Life remembers read-only file handles on the approved origin, can refresh with one click, and can check every minute while visible. It never signs into Microsoft, scans your folder, fetches a sharing URL or writes to those files. Browser permission may need reconnecting after a reload. Closed or hidden pages do not refresh.

OneDrive for Business is classified as a standard Power Automate connector. Reusing an existing school connection with file read/write entitlement may avoid paid actions and a new Entra app registration. This is conditional on the school’s actual licence, DLP policy and export rules. It does not guarantee that Sebastian may add an action without school approval. No HTTP, premium connector, public share link or new Microsoft Graph permission is required by the selected-file route.

First: use an approved origin

Public Pages builds accept only built-in synthetic data. They disable personal entry, file import, backup restore and linked-file access. A project path such as seb-simpson.github.io/Little-Life/ shares storage and scripting authority with other projects at that hostname; changing the storage-key prefix does not protect it. Encryption at rest alone would not protect an unlocked app from another page on that origin.

For personal data, a deployment operator must build for one explicitly approved, dedicated HTTPS origin at its root, serving only trusted Little Life code. The app checks the exact origin and root path. GitHub’s shared github.io origin is blocked even if placed on an allowlist. Do not reuse an account-wide custom domain that also hosts other apps. Root localhost development is available for testing; it is not a school-approved production deployment or an assertion that the local device is safe.

npm run build -- --private-origin https://YOUR-APPROVED-DEDICATED-HOSTNAME
# Deploy only dist/ to that exact dedicated hostname, at /.
# Default npm run build always produces a synthetic-only public demo.

This requires a suitable existing approved hostname/host; no new paid service is necessary if one is available. A custom domain, new hosting account or IT-hosted location may require separate action. There is no promise of a permission-free private production host. Never change managed-device settings to bypass a block. If a trusted origin is unavailable, use the public synthetic demo until the deployment decision is approved.

Step 1 — Prepare the private folder

  1. Open your school OneDrive using its normal school sign-in. Confirm that keeping these minimal exports on the managed laptop and in browser-local storage is permitted. Do not copy other pupils’ data, grades, email bodies or attachments.
  2. Create a private folder called Little Life. Do not select Share or create any “Anyone” link. Make the folder available through the OneDrive sync already present on your laptop. If Files On-Demand needs to download a file, use normal permitted OneDrive behaviour.
  3. In Little Life’s wizard, download the SOCS and Teams starter JSON. These contain only synthetic examples, not connection settings. The default coverage is partial.
  4. After replacing the example content through the mapping below, the two fixed destination names should be socs.json and teams.json. Keeping the same OneDrive file identity helps the browser retain access.

Step 2 — Copy the existing SOCS flow

  1. Open Power Automate through your school’s usual route. Under My flows, find the working SOCS flow. Use Save as (or the available copy option) so that the existing retrieval is preserved. Name the copy Little Life — SOCS export. Do not export a full flow package into GitHub or paste its definition into Little Life.
  2. Retain the existing trigger, school connection and retrieval steps. Check that the retrieval includes every page and the intended date range. In the export copy, set trigger concurrency to one if available, to prevent an older run overwriting a newer export. Do not bypass a disabled policy setting.
  3. Add Data Operation → Select. Its From is the array produced by the successful SOCS retrieval step. Map externalId, type, category, title, start, end, status, updatedAt, and optional location. The exact SOCS dynamic-content names depend on your existing flow and have not been supplied, so do not guess them. Identify them from a permitted successful run. If unsure, keep the export partial and check with the flow owner/IT.
  4. Set type to event. Academic lessons must use category lesson; clubs/fixtures/co-curricular events use activity. If your current array mixes them, use the actual source classification or two Select steps and combine their arrays. Unidentified records use unclassified, which prevents a free-time claim. Do not classify all SOCS records as lessons.
  5. Retain the real stable event/instance ID, original start for moved recurrence instances, actual source modification time, and explicit cancellation status. Convert local timestamps properly to UTC or explicit offsets; never simply append Z. If a source has no stable change timestamp, retain a first-seen timestamp in the exporter and advance it only when content changes. The app rejects same-time conflicting versions.
  6. Add Data Operation → Compose named LL_Export and assemble the object in the v2 contract. For the items value, insert the Select output as an array using the expression/dynamic-content editor, not quoted text. Use the real successful retrieval time for coverage observedAt and lastSuccessfulSyncAt. exportedAt can use utcNow() when packaging finishes. Export start/end must match the actual queried range.
  7. Include separate coverage windows for lesson and activity. Initially mark both partial. Only mark one complete after checking it includes all your relevant records, all result pages and known updates/cancellations for that interval. If the flow cannot detect source deletions/cancellations, it cannot safely promise complete current coverage. A school-wide public calendar is not proof of your personal timetable.

Step 3 — Save or update the same OneDrive file

  1. In the copied flow, after successful retrieval and LL_Export, add OneDrive for Business → Create file for the first setup run. Choose folder /Little Life, file name socs.json, and file content from the expression string(outputs('LL_Export')). The action’s internal name must match your actual Compose step; select its dynamic content if Power Automate assigned another name.
  2. Run the copied flow once through its normal test controls. In OneDrive, inspect the file: it must begin with an object {, contain an items array, and not be a quoted string of escaped JSON. Do not proceed if it contains credentials or unrelated school data.
  3. For subsequent runs, replace the Create file action with OneDrive for Business → Update file, selecting that existing socs.json with the file picker. Keep the same file content expression. Use a stable file identifier. Do not delete/recreate or generate timestamped file names for every run.
  4. Configure this final export/update step to run only after retrieval and mapping succeed. If a retrieval fails, leave the previous file untouched; its observed timestamp will become stale in Little Life. Do not write an empty file with a new “successful” observation timestamp. Only change the flow’s schedule using settings already allowed by the school.
  5. Wait until the existing OneDrive client reports that the updated file is synced. If an action asks for premium licensing, new broad access or prohibited data transfer, stop and retain the existing working flow. Ask IT about the permitted standard route; do not start a paid trial or weaken policies.

Step 5 — Link in Little Life

  1. Open the approved private deployment in an already-approved compatible browser, choose Use my data, then Integrations. On a public Pages build this action is intentionally unavailable.
  2. In the wizard, review required scopes: SOCS lessons and activities, Outlook personal events, and Teams assignments. Default freshness limits are 12 hours, 12 hours, 6 hours and 24 hours respectively. If you truly manage all personal events manually and do not use Outlook for personal events, explicitly select that option and save the scope. It does not remove the lesson/activity requirements.
  3. Select Link and read SOCS file. In the browser’s file picker, navigate to the existing school OneDrive Little Life folder and choose socs.json. Grant read permission only to the selected file if prompted. The source is checked before its handle is remembered. Repeat with teams.json.
  4. Inspect the timeline, cancellations, category labels and overlap warnings. Compare a representative week to the real source apps. Test a moved/cancelled event, an unchanged rerun and an assignment without a due time. File processing alone does not establish full coverage or independently verify source content.
  5. Click Refresh linked files after a flow/OneDrive update, or enable Check every minute while this page is visible. This rereads existing handles without another manual import. After a reload, use Reconnect if the browser needs read permission again. Never change school restrictions to force access.
  6. Keep an approved backup. Forgetting a file stops future reads but retains imported records. To revoke the browser’s file access, use its normal site settings; to remove records, use workspace reset after backing up. Stopping the export copy does not alter the original working flow.

Troubleshooting

  • Free time unknown: open the coverage details. A missing Outlook personal feed, partial lesson/activity window, unknown event category/time, failed import or stale observation suppresses gaps. Refreshing an old file cannot fix this.
  • Read permission needed: click the source’s Reconnect button. Permission is requested only on your click. If denied by policy, ask IT; manual import remains available on the approved origin.
  • File unavailable: wait for OneDrive sync, check the file’s normal availability, then relink it if a OneDrive replacement changed its identity. The app never scans the folder to find substitutes.
  • Wrong source / invalid JSON: choose the correct file and inspect the Select/Compose output. The previous records are preserved. Fix the exporter rather than modifying the app’s stored data.
  • Complete windows but uncertain schedule: check other required categories and actual window boundaries. Coverage is source-specific; a fresh Teams export does not prove your academic timetable is complete.
  • Browser unsupported: manual import is a fallback. Use an already permitted Edge/Chrome with File System Access support. Do not enable experimental flags or override school browser policy.

Why a private OneDrive link alone is insufficient

A normal authenticated OneDrive sharing page is not a JSON endpoint a static app can silently read. A direct Graph implementation would require an approved app registration, delegated file access and tenant consent rules. Microsoft documents Files.Read and a preauthenticated download-URL pattern for JavaScript downloads; it is not an anonymous-link workaround. Little Life implements neither a public-share route nor a proxy. The selected-file bridge avoids adding that Microsoft app permission.

Chrome documents user-gesture file selection, read permission and storing handles in IndexedDB. This is a browser-local permission, not proof the school allows exporting the data. Remaining checks are: school approval, actual flow output mapping, OneDrive standard action entitlement, coverage completeness/cancellation handling, sync behaviour and file-handle persistence on Sebastian’s managed browser.
