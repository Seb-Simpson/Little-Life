Integration feasibility & safe connection guide

No live school integration is verified in Little Life. Sebastian reports that his existing Power Automate flows retrieve SOCS events and Teams assignment information successfully. Their definitions, outputs, permissions, completeness and continuing operation have not been inspected here. Public documentation establishes a supported route; the demonstration workspace establishes no account connectivity.

Recommended route for this phase

Retain the school-approved retrieval that already works. Add a minimal JSON export to a copy of each flow, save it within an approved school location, and explicitly import that file into the personal workspace. This avoids a new account connection and keeps the browser prototype free to run. First confirm that school policy permits this local use of exported data. No Power Automate changes were made in LL-001.

GitHub Pages hosts static public application files. It cannot receive private webhook payloads, run scheduled ingestion, store a client secret, or update browser storage while the page is closed. LL-001 implements file import and manual entry only. A flow may run on a schedule, but its data does not automatically reach Little Life. There is no “Connect” button that pretends otherwise.

Safe first connection: actions for Sebastian

  1. Ask school IT whether the selected personal data may be exported to local browser storage on the managed laptop. Keep using the school’s normal sign-in. If blocked, retain manual entry and demonstration mode.
  2. Make a copy of each working flow. Keep retrieval and authentication unchanged. Choose a short range, for example today plus the next seven days. Export only your own necessary data to an approved school-managed destination.
  3. Map it to schema version 1. Keep source IDs stable, preserve actual source modification times, and use UTC or explicit-offset timestamps. Do not turn a missing deadline into midnight or invent cancellation data.
  4. For SOCS, check lesson and co-curricular coverage separately. For Teams, include class-scoped assignment IDs. Do not export the same SOCS feed through Outlook and the SOCS flow.
  5. Open Little Life on an approved browser/origin, choose Use my data, then Your data. Select the JSON file, preview it, and inspect the counts before importing. The JSON never leaves the browser through this application.
  6. Compare the timeline against the source application: exact dates, time zones, all-day boundaries, recurrence, known free periods and at least one changed/cancelled event. Import the same file twice; the second run should be unchanged. Test a revised version and a missing-deadline record.
  7. Record the check, scope and upstream run time privately. A local import updates “Last successful local import”; upstream timestamps remain explicitly reported and unverified. LL-001 intentionally has no toggle that falsely verifies a school connection.
  8. Keep a local backup, and check run history/source freshness before relying on the schedule. To disconnect, stop the export flow or remove its added export step, reset the personal workspace, and remove private downloaded files through approved school processes. Revoke any future app consent through IT if needed.

Routes deferred to LL-002

A direct Graph adapter would use an IT-approved single-tenant SPA registration with an exact redirect URI and MSAL authorization code flow with PKCE. Public client code must not contain a client secret. Refresh/authentication state, permissions and Conditional Access need testing on the managed device. Microsoft’s MSAL Browser documentation describes this supported model. Credentials will not be collected by Little Life forms.

For unattended data delivery, choose an approved private authenticated destination and threat model first. Do not place school payloads in a public repository, public Pages JSON, URL query strings or unauthenticated endpoints. A service worker or Lively wallpaper does not itself provide a secure background integration.

Evidence and limits

The repository includes executable scheduling, persistence, deduplication and missing-data tests. Automated checks exercise the engine with synthetic records. Browser UI and visual QA could not run because the managed preview relay failed to become ready. No Microsoft, SOCS or school account was accessed. No flow was edited and no permission was requested. Automatic sync, tenant consent, licence entitlements, real data completeness and Lively compatibility remain unverified.

Additional primary references: Graph permissions and consent, Power Platform data policies, Power Automate licensing FAQ. School policy and actual tenant configuration determine what is allowed.
