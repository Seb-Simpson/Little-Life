# LL-002 architecture

Continued from `fd89950`. A static browser application with pure scheduling and deterministic briefing modules. Only development tests depend on Playwright; no runtime dependency, backend, Microsoft login, remote AI or analytics is present. CSP retains `connect-src 'none'`.

The v2 model retains stable source/ID pairs and explicit-offset timestamps, adds event category and source coverage windows, and migrates v1 data without inventing coverage. State keeps the existing localStorage key to preserve upgrades, but the validated workspace schema is now 2. Source verification remains unverified. Exporter-supplied observedAt and completeness are reported claims, never connection verification. Coverage windows are category-specific and bounded. An older export cannot replace newer coverage; conflicting metadata at the same export timestamp rejects the batch. Existing record-level change, stale-version and cancellation rules remain intact.

`intelligence.js` consumes the engine, not DOM content. It assesses each required source/category independently, joins fresh complete windows without bridging gaps, checks stale/failed/unknown data, detects active overlaps, and derives a schedule snapshot. `availabilityForDay` requires coverage plus complete times/categories before using the low-level `freeWindows` interval subtraction helper. Consumers must use the coverage-aware API for user-facing free-time claims. Assignment deadlines do not occupy calendar time; their own coverage affects briefing uncertainty. Current and next use the clock independently of a browsed day. Lookahead is explicitly 14 days. The daily deterministic briefing returns five answers plus supporting record IDs; no generated event or remembered personal inference is added.

`privacy.js` gates personal data before reading the personal workspace, file selection/reads, restore, form save or import. `deployment-policy.js` is code-controlled configuration; there is no user checkbox to bypass shared-origin isolation. Default build replaces it with publicDemoOnly true and allowLoopback false. Private builds require a dedicated exact HTTPS origin at root; github.io and subpaths are denied. Trusted development at root localhost is available in source. Encryption was not presented as a fix for an unlocked shared-origin app: another page at that origin has scripting authority. The deployment must host only this trusted app, with no unrelated scripts/apps/service workers at that origin. Storage remains unencrypted on an approved origin, subject to school policy and backups.

`linked-files.js` is a read-only selected-file adapter. It remembers actual browser file handles in IndexedDB only on an allowed origin after source validation and successful local processing. It never accepts a URL, enumerates a directory or writes school exports. File permission is queried before every read; prompts require an explicit reconnect action. The app imports each linked source atomically through the same parser/model/repository as manual imports, retaining previous records on failure. Optional 60-second checking runs only while the page is visible. A local read updates lastImportAt, never observedAt. Forget removes the handle, not records or the browser’s retained grant. Site-settings revocation is documented.

Coverage requirements default to SOCS lesson/activity at 720 minutes, Outlook personal at 360 and Teams assignment at 1440. The wizard can explicitly opt out of the Outlook personal feed when personal events are all manual; academic requirements remain mandatory. A source with no successful import is not automatically considered unused. Advanced requirement changes are validated state, not inferred from absent records.

The storage adapter still validates every load/save, preserves corrupt/future data for recovery, uses revisions and Web Locks where available, and separates demo/personal modes. A browser without Web Locks retains a small true-simultaneous-write race; use one editing tab. Backups are private workspace files. Native file handles and local records do not synchronise across devices. Existing OneDrive sync is external to Little Life and remains unverified on the school device.

The default build emits only static source/docs/synthetic examples and an enforced public policy. The manual Pages workflow tests and publishes that public build only. Browser tests use real Chromium, native storage and OPFS file handles; picker selection and revoked-permission outcomes are simulated. They do not prove Windows sync or actual tenant behaviour. Future companion/house renderers should subscribe to immutable engine snapshots and evidence-labelled answers, not bypass coverage logic or use journal text as automatic memory.
