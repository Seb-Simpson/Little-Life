# LL-002 recommendation

Make real data trustworthy before adding the animated house.

1. **Validate one approved export route.** Sebastian and school IT confirm local storage/export policy. Use copies of the working SOCS/Teams flows, minimal fields and an approved destination. Map stable IDs, UTC/offset times, source modifications and cancellations. Import one representative week; compare source and app. Exit: repeat import adds zero duplicates, moved/cancelled occurrences match, missing deadlines stay unknown, and academic/co-curricular coverage is written down.
2. **Add scoped evidence and freshness.** Introduce verification records (who checked, method, time, source scope and expiry), coverage windows and stale thresholds. Distinguish complete, partial, delayed, forbidden and unavailable sources. Surface gaps in the dashboard and verify free periods against the actual timetable. Add a change history and a clear failed-run view. Exit: stale/partial data never appears complete or current.
3. **Choose the delivery architecture with IT.** Default to continued manual JSON imports if policy or licensing blocks more. If approved, add MSAL PKCE with minimal delegated calendar scope on an exact single-tenant redirect URI, then optional mail metadata. Teams requires administrator consent. Test on the managed laptop. For closed-page delivery, design a private authenticated relay only if an approved, free entitlement exists. Exit: documented permission/consent, revocation, retention, cost and failure behaviour; no secrets in static assets, logs or repository.
4. **Harden personal persistence.** Move behind an IndexedDB repository with transactional imports, migration/recovery checks, bounded change history and backup UX if volume grows. Add tests for real (privately held) redacted edge cases and browser automation in CI once tooling is chosen. Exit: update, restore and cancellation rehearsals pass on the school browser; no school fixtures committed to GitHub.
5. **Create one read-only companion view.** A small animated room and companion can subscribe to the engine’s activity snapshot. Start with local deterministic daily briefings and opt-in explicit memories. Do not infer private facts into persistent memory. A future conversation system must distinguish verified data, reported data and inference. Exit: visual changes cannot alter schedule truth; no remote AI request without a separate authorised design and cost decision.
6. **Evaluate ambient mode on an approved Windows device.** Build a separate lightweight, read-only renderer with reduced motion, no sensitive email/journal text by default, and pause on hidden/inactive screens. Test Lively’s actual web runtime, local file/HTTP origin, storage partitioning, reloads and device policy. Do not assume it shares the normal browser’s storage. Decide an explicit approved data hand-off. Exit: documented working setup on the target device; no managed-device restrictions bypassed. Full Lively support remains a future feature, not an LL-001 claim.

Order: trusted data → evidence/freshness → approved delivery → resilient storage → house/companion → Lively. Automatic email understanding and remote AI should wait until these boundaries are established. LL-002 can remain free if it retains manual delivery and local deterministic behaviour; do not promise free background hosting or AI usage.
